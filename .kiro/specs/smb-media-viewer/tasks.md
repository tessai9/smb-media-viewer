- [x] 2. (P) 設定モジュールを実装する
  - `YAML::Serializable` を使って設定構造体を定義し、5つの設定項目（`media_root`、`cache_dir`、`port`、`thumbnail_size`、`items_per_page`）とデフォルト値を持たせる

  - アプリ起動時に1回だけ読み込んでグローバルな定数として保持し、実行中の再読み込みは行わない
  - `YAML.mapping`（非推奨API）は使用しない
  - _Requirements: 7.1, 7.2, 7.3_

- [ ] 3. (P) MIMEタイプサービスを実装する
  - 対応するすべての拡張子（画像7種・動画5種・PDF）を `MediaType` 列挙型（`Image / Video / Pdf / Unknown`）にマッピングする
  - ファイル名から `MediaType` を返す関数、Content-Type 文字列を返す関数、一覧表示対象かどうかを返す関数を実装する
  - 拡張子の大文字小文字を区別せずに判定する
  - ファイル I/O は行わず、ファイル名文字列のみを入力として受け取る
  - _Requirements: 1.5, 2.2, 2.3, 2.4_

- [ ] 4. ファイルブラウザを実装する
- [ ] 4.1 パス安全性検証を実装する
  - `media_root` と相対パスを受け取り、正規化後に `media_root` 配下であることを検証する
  - `..` や絶対パスを使って `media_root` の外を指す場合は `nil` を返す
  - 正常なパスの場合は絶対パスを返す
  - 呼び出し元は `nil` 返却時に必ず 400 または 404 を返すこと（不変条件として文書化する）
  - _Requirements: 6.1, 6.2_

- [ ] 4.2 ディレクトリ走査・フィルタリング・ソートを実装する
  - パス安全性検証を通過したパスのディレクトリ内容を列挙し、`FileEntry` 構造体の配列として返す
  - 隠しファイル（`.` 始まり）と非対応拡張子ファイルを除外し、ディレクトリは常に含める
  - ディレクトリを先に、その後ファイルを並べ、各グループ内はアルファベット順（大文字小文字無視）でソートする
  - 各エントリに名前・相対パス・ディレクトリフラグ・サイズ・更新時刻・メディア種別を設定する
  - 同一ディレクトリ内での前後エントリ参照（ビューア用ナビゲーション）もこの一覧順に基づく
  - _Requirements: 1.3, 1.4, 1.5, 2.5_

- [ ] 4.3 ページング対応を実装する
  - `offset` と `limit` を受け取り、ソート済みエントリ配列から該当範囲を切り出して返す
  - `limit` は内部で最大 100 にクランプし、エラーは返さない
  - `offset >= 0` であることを前提とし、範囲外の場合は空配列を返す
  - _Requirements: 1.6_

- [ ] 5. (P) サムネイルサービスを実装する
- [ ] 5.1 キャッシュキー生成とディスクキャッシュ管理を実装する
  - ファイルの絶対パスと mtime の Unix タイムスタンプを連結した文字列の SHA256 ハッシュ値をキャッシュキーとして使用する
  - キャッシュファイルが存在する場合はそのパスを返し、存在しない場合は生成処理に進む
  - 起動時にキャッシュディレクトリが存在しない場合は自動作成する
  - mtime が変化したファイルは新しいキャッシュキーで自動的に再生成される（古いキャッシュは残置し、将来的なクリーンアップは対象外）
  - 生成失敗時は例外を伝播させず `nil` を返し、STDERR にエラーをログ出力する
  - _Requirements: 4.2, 4.6, 4.7_

- [ ] 5.2 各メディア種別のサムネイル生成を実装する
  - 画像: `vipsthumbnail` を使ってソースファイルを指定サイズ（最大辺 px）に縮小し JPEG 出力する
  - 動画: `ffmpeg` で 1 秒地点のフレームを一時ファイルに抽出後、`vipsthumbnail` でリサイズし、一時ファイルを削除する
  - PDF: `pdftoppm` で 1 ページ目を JPEG に変換（出力ファイルは glob で特定）後、`vipsthumbnail` でリサイズし、一時ファイルを削除する
  - 外部コマンドはシェル展開を経由しない形式で呼び出し、終了コードが非 0 の場合は失敗として扱う
  - 外部コマンドが PATH 上に存在しない場合もクラッシュせず `nil` を返す
  - _Requirements: 4.3, 4.4, 4.5, 4.6_

- [ ] 6. ECR ビューテンプレートを実装する
- [ ] 6.1 (P) 共通レイアウトとディレクトリ一覧テンプレートを実装する
  - 共通レイアウト（HTML シェル、nav、CSS/JS 読み込み、子テンプレート埋め込み）を作成する
  - ディレクトリ一覧テンプレートは `FileEntry` の配列を受け取り、CSS Grid のサムネイルグリッドを出力する
  - 各サムネイル `<img>` は `src=""` を空にし、`data-src` に実際の URL を設定する（遅延読み込み用）
  - ページ末尾に番兵要素（`<div id="sentinel">`）を配置する（無限スクロール用）
  - 初回バッチ（`items_per_page` 件）は SSR でテンプレート内に含める
  - _Requirements: 1.2, 1.3, 2.2, 2.3, 2.4, 5.1_

- [ ] 6.2 (P) 個別ビューアテンプレートを実装する
  - `FileEntry`・前エントリ・後エントリを受け取り、メディア種別に応じたビューアを出力する
  - 画像は `<img>` タグで表示し、動画は `<video controls>` タグでブラウザネイティブプレイヤーに委ねる
  - PDF は `<object>` タグでブラウザ内蔵ビューアに委ね、非対応ブラウザには `<a download>` リンクをフォールバックとして表示する
  - 同一ディレクトリ内の前後ファイルへのナビゲーションリンクと、一覧ページに戻るリンクを表示する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [ ] 7. HTTP ルーターとエントリポイントを実装する
- [ ] 7.1 ディレクトリ閲覧ルートと JSON API ルートを実装する
  - `GET /` → `/browse/` への 302 リダイレクト
  - `GET /browse/` および `GET /browse/*path` → パス検証後にディレクトリ内容を SSR HTML で返す。パス違反は 400、存在しないディレクトリは 404 を返す
  - `GET /api/files/*path` → `offset`・`limit` クエリパラメータを受け取り、`FileEntry` 配列を JSON で返す
  - CIFS マウント切断等のファイルシステム例外を捕捉して 500 を返す
  - _Requirements: 1.1, 1.2, 1.6, 6.2_

- [ ] 7.2 ビューアルート・ファイル配信ルート・動画 Range リクエスト対応を実装する
  - `GET /view/*path` → パス検証後に種別に応じたビューアページを SSR HTML で返す
  - `GET /raw/*path` → パス検証後にファイル本体を適切な Content-Type ヘッダーとともに配信する
  - 動画ファイル配信時には常に `Accept-Ranges: bytes` ヘッダーを付与する
  - `Range` ヘッダーが指定されている場合は HTTP 206 で指定バイト範囲のみ返し、`Content-Range` ヘッダーを設定する
  - `Range` ヘッダーが指定されていない場合は HTTP 200 でファイル全体を返す
  - _Requirements: 2.1, 2.6, 3.1, 3.2, 3.3, 6.1, 6.2_

- [ ] 7.3 サムネイルルートとサーバー起動を実装する
  - `GET /thumbnail/*path` → パス検証後にサムネイルサービスを呼び出し、取得できた場合は JPEG を返す
  - サムネイル生成失敗（`nil` 返却）時は `public/no-thumbnail.svg` に 302 リダイレクトする
  - 設定で指定されたポートで Kemal を起動する
  - _Requirements: 4.1, 4.6, 7.3_

- [ ] 8. (P) フロントエンドを実装する
- [ ] 8.1 (P) CSS グリッドレイアウトとダークテーマを実装する
  - ダークテーマを基調とした CSS を作成する（背景・テキスト・リンクの配色）
  - CSS Grid でサムネイルグリッドを実装し、スマートフォン幅でも適切にリフローする
  - ナビゲーションバー・ビューアページのレイアウトを実装する
  - ファイルサイズは 3 KB 以下を目標とし、外部 CSS フレームワークは使用しない
  - _Requirements: 1.2_

- [ ] 8.2 (P) IntersectionObserver による遅延読み込みと無限スクロールを実装する
  - `IntersectionObserver` でサムネイル `<img[data-src]>` を監視し、画面内に入ったら `src = data-src` をセットして画像を読み込む
  - 画面外に出たサムネイルは `src = ""` にしてブラウザの画像デコードキャッシュを解放する（DOM は残す）
  - `IntersectionObserver` でページ末尾の番兵要素を監視し、可視状態になったら `/api/files/*` を fetch して次バッチの FileEntry カードを DOM に追記する
  - `typeof IntersectionObserver === 'undefined'` で分岐し、非対応ブラウザでは全 `<img>` の `src` を即時セットするフォールバックを実行する
  - ファイルサイズは 4 KB 以下を目標とし、外部ライブラリは使用しない
  - _Requirements: 5.2, 5.3, 5.4, 5.5_

- [ ] 9. テスト
- [ ] 9.1 サービス層のユニットテストを実装する
  - MimeService: すべての対応拡張子（大文字小文字含む）が正しい MediaType と Content-Type を返すこと、非対応拡張子・隠しファイルが `false` を返すことを検証する
  - FileBrowser: `safe_path` が `..`・絶対パス・正常パスの各ケースで正しく動作することを検証する
  - FileBrowser: ソート順・隠しファイル除外・非対応ファイル除外・ページング・limit クランプの正確性を検証する
  - ThumbnailService: 同一入力（パス + mtime）が常に同一キャッシュキーを生成することを検証する
  - _Requirements: 1.3, 1.4, 1.5, 6.1_

- [ ] 9.2 HTTP 統合テストとパストラバーサル検証を実装する
  - `GET /browse/*path` が SSR HTML を返し、正しい FileEntry 情報を含むことを検証する
  - `GET /api/files/*path` が正しい JSON スキーマと offset/limit 適用結果を返すことを検証する
  - `GET /raw/*path` に Range ヘッダーを送信して 206 レスポンスと正しい `Content-Range` ヘッダーを検証する
  - `../../etc/passwd` 等のパストラバーサルリクエストが 400/404 を返すことを検証する
  - _Requirements: 1.6, 3.1, 3.2, 3.3, 6.1, 6.2_

- [ ]* 9.3 サムネイル生成と統合フローのテストを実装する
  - `GET /thumbnail/*path` でサムネイルが生成・キャッシュされ JPEG が返却されることを検証する
  - 外部コマンドが存在しない環境でサムネイル nil フォールバック（302）が動作することを検証する
  - mtime 変更後に再アクセスすると新しいキャッシュキーで再生成されることを検証する
  - _Requirements: 4.1, 4.2, 4.6, 4.7_
